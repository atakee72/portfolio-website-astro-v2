## Problem

A 50-year-old Berlin translation office (German ↔ Turkish specialty,
office-based "vom Original" sworn translations) needed a real site —
not a Wix template — that read as expert, intake-ready, and bilingual
end-to-end. Strict German-jurisdiction GDPR rules out the obvious
shortcuts: no Google Fonts CDN, no third-party trackers, no consent
banners covering up a privacy mess.

## Build

Static Astro 6 with Tailwind 4 (tokens in `@theme`, no config file) and
Svelte 5 islands for the few stateful pieces — FAQ accordion, document
register, contact wizard, voice assistant. The whole site is bilingual
DE / TR: shared UI-string dictionary for chrome, separate Turkish pages
under `/tr/` for long-form copy, route-aware language switcher with
`hreflang` alternates.

The intake flow is a single OrderWizard (service → languages → document
description with file upload ≤ 10 MB → quote-vs-order toggle → contact)
that posts to Web3Forms — no booking calendar, one CTA target sitewide.
The office map is a self-hosted PNG stitched from OSM tiles, not a live
embed, so the contact page transfers zero data to a tile provider.

## Architecture

GDPR-first: the default page loads **zero** third-party scripts and
sets zero cookies, so there's no banner. The voice assistant
(`CallAgent.svelte`) is the single exception — it's **consent-gated**.
Until the user clicks accept, nothing loads: no SDK, no socket. On
accept, a Cloudflare Pages Function mints an **ephemeral Gemini Live
token** (the real `GEMINI_API_KEY` lives server-side, never in the
browser), the `@google/genai` SDK lazy-loads, and a native-audio
session opens. The agent stays general-info only, refuses PII, routes
real orders into the OrderWizard, and stores nothing.

Self-hosted Inter / Manrope / Instrument Serif / Homemade Apple (woff2,
preloaded above the fold). Hosting on Cloudflare Pages with cookie-less
Web Analytics, security headers in `public/_headers`, sitemap + `llms.txt`
for AEO. Bilingual JSON-LD (`LocalBusiness`, `Person`, `FaqPage`,
`DefinedTerm` for the glossary).

## Reflection

The original brief was an AI **phone** receptionist (telephony via n8n
+ IONOS). After exploring it, we shipped a consent-gated **in-browser**
voice assistant instead — GDPR-cleaner, loads zero third parties until
the user explicitly opts in, and works on any device with a microphone.
The phone angle is parked, not dead; the chat-FAB stub next to the
voice button is the mount point for a text-only sibling once the FAQ
corpus is ready. The lesson was that "AI assistant" doesn't have to
mean "telephony" — the right channel is the one your privacy story can
actually defend.
