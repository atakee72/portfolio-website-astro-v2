## Problem

A Berlin translation office — German ↔ Turkish specialty, interpreter
practice since 1971, GmbH since 1984, sworn "vom Original" translations
handed over in person — needed a real site that read as expert and
intake-ready, in both languages, without falling into the usual
GDPR-shortcut traps: no Google Fonts CDN, no third-party trackers
loaded up front, no consent banner covering up a privacy mess.

## Build

Static Astro 6 with Tailwind 4 (tokens in `@theme`, no config file) and
Svelte 5 islands for the stateful pieces — FAQ accordion, document
register, contact wizard, testimonials marquee, voice assistant. The
whole site is bilingual DE / TR: shared UI-string dictionary for
chrome, separate Turkish pages under `/tr/` for long-form copy,
route-aware language switcher with `hreflang` alternates.

The intake flow is a single OrderWizard (service → languages →
document description with file upload → quote-vs-order toggle →
phone-validated contact via `libphonenumber-js`). Documents go through
**Cloudflare R2** with signed links (the old Web3Forms direct-upload
path was capped and started returning HTTP 400 on real files). The
submit endpoint is gated by **Cloudflare Turnstile** — invisible, no
cookies, so no consent needed. Uploads carry magic-byte validation and
per-IP rate limits stored in **Cloudflare KV**.

The office map is a self-hosted PNG stitched from OSM tiles, not a
live embed, so the contact page transfers zero data to a tile
provider.

## Architecture

GDPR-first, revisited: the default page still loads zero third-party
*visitor-visible* scripts, so there's no cookie banner. Two subtleties
under that:

- **Voice assistant** (`CallAgent.svelte`) is **consent-gated**. Until
  the user clicks accept, nothing loads. On accept, a Cloudflare Pages
  Function mints an ephemeral Gemini Live token (`GEMINI_API_KEY` stays
  server-side), the `@google/genai` SDK lazy-loads, and a native-audio
  session opens. The agent stays general-info only, refuses PII,
  routes real orders into the OrderWizard, stores nothing.
- **Observability** is Sentry, **EU-region** — but shaped to the
  privacy story. Server-side (Pages Functions) is unconditional and
  invisible to visitors. The browser-side reporter is **custom,
  dependency-free, and armed only after voice consent** — it exists
  only to catch voice failures the user is already inside; no
  page-load telemetry, no breadcrumbs, no SDK bundle.

Self-hosted Inter / Manrope / Instrument Serif / Homemade Apple
(woff2, preloaded above the fold). Cookie-less Cloudflare Web
Analytics, security headers in `public/_headers`. Rich JSON-LD entity
graph (`LocalBusiness` with `foundingDate`, `Person`, `FaqPage`,
`DefinedTerm` for the glossary) plus `llms.txt` and freshness signals
for the SEO/GEO program.

## Reflection

The original brief was an AI **phone** receptionist (telephony via n8n
+ IONOS). After exploring it, we shipped a consent-gated **in-browser**
voice assistant instead — GDPR-cleaner, loads zero third parties until
the user explicitly opts in, and works on any device with a microphone.
The lesson generalised: the same "no third party until the user is
already inside a voluntary experience" pattern shaped the error-reporting
decision too. Server-side observability sits where it doesn't touch
the visitor; browser-side error capture only arms after they've
accepted the voice channel. Privacy isn't a constraint you route
around — it's a design that keeps working as the feature list grows.
